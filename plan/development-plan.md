# แนวทางพัฒนา Portal ผลงานนักเรียน (แนว Social)

เป้าหมาย: ให้ผู้ใช้มีส่วนร่วมขับเคลื่อนเว็บไซต์ โดยครูไม่ต้องบริหารเอง
หลักคิด: **ผู้ใช้สร้างข้อมูลเอง · ระบบคัดเลือกเอง · ชุมชนช่วยดูแลกันเอง · ครูตรวจเมื่อมีเรื่องผิดปกติ**

## 1. ให้นักเรียนจัดการข้อมูลของตัวเอง

หลัง login ด้วยบัญชี `@pccpl.ac.th` นักเรียนควรทำเองได้:

- แก้ชื่อผลงาน คำอธิบาย รูปปก และแท็ก (เช่น เกม, พอร์ตโฟลิโอ, วิทยาศาสตร์)
- ผูกเว็บ `userXXXX` กับโปรไฟล์ของตัวเอง (ยืนยันตัวตนด้วยอีเมลโรงเรียน)
- ถ้าเว็บโดนบล็อก iframe ให้ระบบแคปหน้าจอเป็นภาพปกอัตโนมัติ

## 2. ให้ชุมชนเป็นคนคัดเลือก

| ฟีเจอร์ | รายละเอียด |
|---|---|
| ไลก์ | 1 คน / 1 ผลงาน, ห้ามไลก์งานตัวเอง |
| ยอดเข้าชม | นับแบบไม่ซ้ำคนต่อวัน |
| คอมเมนต์ / บันทึกโปรด | เฉพาะผู้ใช้ในโดเมนโรงเรียน |
| ไฮไลท์อัตโนมัติ | คะแนน = ไลก์ + ยอดชม + คอมเมนต์ ลดน้ำหนักตามเวลา เพื่อให้งานใหม่มีโอกาสขึ้นหน้าแรก |
| แท็บหน้าแรก | มาแรงสัปดาห์นี้ · ใหม่ล่าสุด · ยอดนิยมของปี · คนที่ติดตาม |

## 3. ให้ชุมชนดูแลกันเอง

- login ด้วยอีเมลโรงเรียนอย่างเดียว ทุกการกระทำมีชื่อเจ้าของ
- ปุ่ม "รายงาน": ถึงเกณฑ์ (เช่น 3 คน) ระบบซ่อนเนื้อหาชั่วคราวและแจ้งครู
- ตัวกรองคำหยาบอัตโนมัติ
- จำกัดอัตราการโพสต์/ไลก์ (rate limit) กันสแปมและการปั่นไลก์
- ระบบบทบาท:
  - **นักเรียน** — จัดการผลงานตัวเอง, ไลก์, คอมเมนต์, รายงาน
  - **ครู** — ซ่อน/ลบเนื้อหา, ดูรายงาน
  - **แอดมิน** — จัดการปีการศึกษา, กำหนดบทบาท

## 4. ทำให้คนอยากกลับมา

- ป้ายรางวัล: "ผลงานแห่งสัปดาห์", "ได้รับไลก์ครบ 50"
- การแจ้งเตือน: "มีคนคอมเมนต์ผลงานของคุณ"
- หน้าโปรไฟล์นักเรียนรวมผลงานข้ามหลายปี ใช้เป็นพอร์ตโฟลิโอตอนสมัครเรียนต่อ
- แคมเปญประจำภาค: นักเรียนโหวต แล้วครูประกาศรางวัลจากผลโหวต

## สถาปัตยกรรมที่ต้องเพิ่ม

ต้องมี **backend + ฐานข้อมูล** และ Google OAuth ที่ตรวจโดเมนฝั่งเซิร์ฟเวอร์ (`hd=pccpl.ac.th`)

**ตัวเลือก**
- **Self-host:** Node.js หรือ Python (FastAPI/Django) + PostgreSQL (หรือ SQLite ถ้าผู้ใช้ไม่เกินหลักพัน) — ข้อมูลอยู่ในเครือข่ายโรงเรียน
- **Backend สำเร็จรูป:** Supabase / Firebase — มี login กับฐานข้อมูลในตัว ทำเร็วกว่า แต่ข้อมูลอยู่นอกโรงเรียน

**ตารางข้อมูลเบื้องต้น**

| ตาราง | ฟิลด์หลัก |
|---|---|
| `users` | id, email, display_name, role, created_at |
| `projects` | id, owner_id, year, username (เช่น user3101), url, title, description, cover, tags, is_hidden |
| `likes` | user_id, project_id, created_at (unique คู่ user+project) |
| `views` | project_id, viewer_id, day (unique ต่อวัน) |
| `comments` | id, project_id, user_id, body, is_hidden, created_at |
| `reports` | id, target_type, target_id, reporter_id, reason, created_at |
| `badges` / `user_badges` | ป้ายรางวัลและผู้ได้รับ |

**ข้อควรระวังเรื่อง Login**
- ตรวจโดเมนอีเมลที่ฝั่งเซิร์ฟเวอร์เสมอ ห้ามเชื่อ front-end
- ใช้ session cookie แบบ HttpOnly + HTTPS

## ความเป็นส่วนตัวและความปลอดภัย (ผู้ใช้เป็นเด็ก)

- คอมเมนต์เปิดเฉพาะผู้ใช้ในโดเมนโรงเรียน คนนอกมองไม่เห็นและโพสต์ไม่ได้
- ไม่แสดงชื่อ-สกุลเต็มในหน้าสาธารณะ ถ้ายังไม่ได้ขออนุญาต
- มีนโยบายความเป็นส่วนตัวแบบสั้น (PDPA) ที่โรงเรียนเห็นชอบ
- เจ้าของผลงานปิดคอมเมนต์ของงานตัวเองได้
- มีช่องทางให้รายงานการกลั่นแกล้ง และครูมีสิทธิ์ซ่อนเนื้อหาได้ทันที

## Roadmap

| Phase | เนื้อหา | ความเสี่ยง |
|---|---|---|
| 1 ✅ | Portal static, ไฮไลท์สุ่ม, ตัวกรองปี/กลุ่ม | ต่ำ |
| 2 | Login Google @pccpl.ac.th, โปรไฟล์, แก้ข้อมูลผลงานตัวเอง | ต่ำ |
| 3 | ไลก์, ยอดชม, ไฮไลท์จากคะแนน (ยังไม่มีคอมเมนต์) | ต่ำ |
| 4 | คอมเมนต์, รายงาน, ซ่อนอัตโนมัติ, บทบาทครู | กลาง |
| 5 | ติดตาม, แจ้งเตือน, ป้ายรางวัล, แคมเปญโหวต | ต่ำ |

> เริ่มจากฟีเจอร์เสี่ยงต่ำ (ไลก์/ยอดชม) แล้วค่อยเพิ่มคอมเมนต์เมื่อระบบรายงานและบทบาทครูพร้อม
